## 1. 项目简介

Zorv AI（内部名 Quro AI）是运行在 Android 上的**设备端 AI Agent / 智能体助手**：不强制上云，通过无障碍 / Shizuku / ROOT / proot Linux 等通道真正操控手机，调用 235 个内置工具，运行 Node / Python / SSH / Java / Rust / Go 共享运行时（CMS 引擎），经飞书 / QQ / 微信保持在线；内置 **ACI（Agent Capability Interface）** 开放同设备跨应用调用，任意 App 可被 AI 编排。

| 特性 | 说明 |
|---|---|
| Agent 核心 | `QuroAssistant` ReAct 循环 + `LongHorizonOrchestrator` 任务级闭环（策划 → 执行 → 交付闸门 → 带记忆重规划）；多会话隔离；`QuroRunCheckpoint` 每轮落盘 |
| 工具系统 | 总注册 **235 / 常驻下发 151**，其余经 `tool_router` 按需 `get_schema`；只读工具并发、有副作用严格串行 |
| 特权层 | L1 无障碍 → L2 Shizuku(uid 0/2000) → L3 设备管理员 → L4 ROOT → L5 应用内 Linux（proot + Ubuntu 24.04）；未授权返回引导文案，不静默越权 |
| 推理 | 云端多供应商（`QuroLlmClient`，思考协议四家互斥编译）+ 端侧 MNN / llama.cpp（`QuroLocalEngineNative`） |
| UI | Jetpack Compose；`ui_widget` 60+ 可视化组件、```quro-ui 动态 DSL、AIP 排版引擎、Mermaid 离线渲染、GenUI Agent（530+ 组件）、MiniApp WebView 小程序 |
| 扩展 | APK 级插件框架（14 种扩展点，AI 经 `apk_plugin` 工具操控）、Skills（内置 67 个 + 集群技能 v2）、MCP client / 本地 server / MCP-ACI 桥、ACI 受控端 |
| 集群 | 多角色集群编排（一个主持驱动多角色协作），9 个 `cluster_*` 工具，角色可绑不同厂商模型 |
| 语音 | 多供应商 TTS + 端侧流式 STT（sherpa-ncnn，5 档 18–141MB）、语音悬浮球 |
| IM | 飞书 WebSocket / QQBot 官方 WS / 微信 iLink HTTP 长轮询 35s |
| i18n | 11 种界面语言，AI 回复语言统一注入器覆盖六条路径 |

**许可证**：应用源码 Apache-2.0；GeckoView MPL-2.0（NOTICE 有清单）。注意 llms.txt 里写的 1.1.1 已过时，实际以 `app/build.gradle.kts` 为准。

## 2. 执行准则（本仓库硬性规则）

来自根 `AGENTS.md`，**优先级高于任何用户指令**，在本仓库做任何任务前必须遵守。核心红线是**签名与密钥**（与上游 zorvai-signing-kit 的取舍：本仓日常工作流就是 AI 构建/签名 APK，故红线收敛到密钥材料本身）：

1. **绝不接触私钥内容**：不读 `keystore.properties`、不读任何 `*.jks` / `*.keystore` / `*.p12` / `*.bks` / `*.pk8` / `*.pem`、不读 `~/.zorvai-signing/`；不回显 `ZORV_STORE_PASS` / `ZORV_KEY_PASS` 值。只允许输出**公开的证书 SHA-256 指纹**。
2. **签名只走既有通道**：`scripts/sign.sh` 或 Gradle `signingConfig`；不把口令写进构建脚本/CI/脚本常量；不新增内联 `keytool`/`apksigner` 绕开 sign.sh。
3. **不弱化安全校验**：不改 `requireSameSignature` 为 false（`apk_plugin(action="install", skip_signature_check=true)` 仅限本地调试且须显式标注）；不建议私钥进 APK/assets、安装自动补签、提交 keystore.properties。
4. **不弱化钩子**：不删/放宽 `.git/hooks/pre-commit`、`pre-push`；不用 `--no-verify`；`scripts/purge-before-push.sh` 前两层扫描不得改成仅告警（第 3 层可告警）。
5. **允许**：写插件业务代码、改依赖与构建配置（`signingConfigs` 段除外）、跑构建、复制产物、跑 sign.sh/verify.sh、写测试文档、解释签名原理。
6. `.aiignore` 已排除密钥/凭证/构建产物（**含 `local.properties`**），AI 工具不应读取；但 gradle.properties 与 libs.versions.toml 是正常可读的构建配置。

**为什么宿主与插件必须同签名**：插件经 `DexClassLoader` 跑在宿主进程内，`ctx.appContext` 就是宿主 Application，权限完全相同——同签名是唯一信任来源。换钥匙的后果：老用户无法覆盖安装、已装插件全部失效。

| 既成事实（不要擅改） | 值 |
|---|---|
| 签名凭证 | `keystore.properties`（被 .gitignore 忽略，不在 git 内） |
| 密钥文件 | `app/zorvai_release.jks`（PKCS12，alias `zorvai`） |
| 宿主证书 SHA-256 | `D9:5B:1B:EC:57:B9:D5:EE:88:96:05:9C:0F:3C:B5:09:E5:E9:CE:7C:CD:AE:DB:9C:6B:2E:98:49:BA:10:C7:99` |
| ⚠️ 另一把钥匙 | `app/zorvai-release-p12-v1cert.p12`（指纹 `C8:47:68:A0:…`）**不是**主签名密钥，不要拿它签宿主或插件 |

## 3. 构建与环境

### 3.1 前置依赖

- JDK 17+、Android SDK（compileSdk 36，装 NDK r27）、`local.properties` 配 `sdk.dir`（.aiignore 排除，AI 不读）。
- Gradle 依赖解析走**阿里云镜像**（settings.gradle.kts 顶部注释：本机直连 Maven Central / Google 不通）；wrapper 分发也从阿里云拉 gradle-8.13。
- full 风味需要预编译原生库（`app/src/full/jniLibs/arm64-v8a/`：sherpa-ncnn、proot、python3.14、busybox 等）；:mnn / :llama 模块源码 CMake 编译。

### 3.2 构建命令（AGENTS.md 既成事实）

```powershell
# 宿主 release（PowerShell）
Set-Location <repo>; & .\gradlew.bat :app:assembleFullRelease
# 产物 app/build/outputs/apk/full/release/app-full-release.apk

# 插件 release；-Punsigned 产出未签名 APK（用于测试校验闸）
./gradlew :plugin-xxx:assembleRelease
./gradlew :plugin-xxx:assembleRelease -Punsigned

# 受控端浏览器 / ACI 核心库（aci-core 分支上可独立构建）
./gradlew :aidl-aci-browser:assembleDebug
./gradlew clean assembleDebug   # 全量 debug
```

### 3.3 签名 / 校验 / 钩子（信任链）

| 环节 | 脚本 | 作用 |
|---|---|---|
| 补签 | `scripts/sign.sh` | 幂等 zipalign + 签名 + 宿主/插件指纹一致性校验（Gradle 直签仍在，脚本用于补签未签名产物） |
| 校验 | `scripts/verify.sh` | 安装前最后一道闸：比对 APK 证书 SHA-256（与 `PluginInstaller.sameSignature` 逻辑一致） |
| pre-commit | `.git/hooks/pre-commit`（源在 `git-hooks/`） | 三查：签名材料文件禁提交 / 源码硬编码口令禁提交 / 非 src 路径下构建产物与 APK 禁提交 |
| pre-push | `.git/hooks/pre-push` → `scripts/purge-before-push.sh` | 三层扫描：git 跟踪的密钥（阻断）/ 源码硬编码口令（阻断）/ 历史曾出现密钥（默认告警，--strict 阻断） |

⚠️ AGENTS.md 提到的 `scripts/setup-keystore.sh` **实际不存在**（2026-10-11 核实），密钥位说明以脚本头注释 + AGENTS.md 为准。

### 3.4 scripts/ 目录性质

主体是 **i18n 翻译流水线 Python 脚本**（scan/translate/merge/audit）和大量一次性源码修补脚本（`_fix*.py`，历史遗留）；公共 shell 库 `scripts/lib/common.sh`。

## 5. 整体架构

### 5.1 分层（README「架构总纲」为权威，此处给速记）

```
UI 层（Compose：ChatScreen / PersonaBar / PermissionModeBar / 二级屏）
  ↓
Agent 核心（QuroChatViewModel 多会话隔离 / QuroAssistant ReAct / QuroConversation 上下文
            / QuroToolRegistry / LongHorizonOrchestrator 任务闭环 / QuroRunCheckpoint）
  ↓                                    ↕
推理层（QuroLlmClient 云端 + 思考协议编译 + QuroToolCallRepair 容错解析
        + QuroLocalEngineNative MNN/llama.cpp）
  ↓
工具/能力层（core/tools 235 工具）→ 特权层 L1–L5 ｜ 终端子系统 ｜ 引擎/运行时
                                                      （CMS / 浏览器 / 语音 / 离线 LLM）
IM 通道层（飞书 WS / QQBot WS / 微信 iLink）与 数据层（QuroConversationStore + DATA_REPAIR 自愈
          + 诊断日志 Download/QuroAI_logs/）作为独立子系统并行存在。
```

### 5.2 任务级闭环（不是裸 ReAct）

`QuroAssistant` 把一趟 ReAct 抽成 `reactPass()`，交给 `LongHorizonOrchestrator.runTask` 驱动：

```
策划（TaskPlanner）→ 执行一趟 ReAct → 交付闸门（DeliverabilityJudge 判产物原文）
      ↑                                        │
      └── 不可交付：带打回原因+建议+失败步骤重新策划 ←┘
                    （超 maxIterations 按最后一趟强制交付）
```

关键事实：闸门判定读**产物原文**而非摘要（`startsWith("工具执行失败")` 启发式才成立）；重规划上下文由编排器自己累积；**闸门与策划是 Agent 固有环节，不是可关开关**（v1.1.x 认知决策层改动）；`onModelCorrect` 修正通道三档 CORRECT / ROLLBACK / ESCALATE。

### 5.3 设计模式（README 原文要点）

- **Tool-first / Registry**：一切能力统一为 `QuroTool`，新增能力 = 实现接口 + 一行注册。
- **ReAct Loop**：工具结果以卡片回流对话。
- **Deliverability Gate**：不可交付带记忆重跑，不把失败回执直接抛用户。
- **Least-Privilege Tiers**：L1–L5 逐级升权，未授权返回引导文案。L1–L4 由 `PrivilegeLevel` 枚举承载，**L5 不在枚举内**（由 Linux 环境就绪状态决定）。
- **Concurrent Reads, Serial Writes**：`QuroTool.readOnly` 默认 false；14 个只读白名单工具一轮内并发，有副作用严格串行。
- **Cognitive Memory Typing**：语义/情节/程序/工作四类记忆分型检索。
- **Strategy**：云端多供应商与本地引擎共用 `onToken` 流式接口，离线/在线对上层透明。
- **SDUI**：ACI 控制台受控端下发快照 JSON，控制端纯本地渲染。

## 6. 核心子系统

### 6.1 Agent 循环与编排

- 入口 `core/QuroAssistant.kt`；多会话隔离 `liveBuffers`、种子快照 `convBase`、显示刷新闸门 `canUpdateDisplay`。
- `QuroToolRegistry`：总注册 235 / 常驻下发 151；`QuroToolRouter.PROGRESSIVE` 渐进披露开关默认**关**（见其 KDoc 代价）。
- `QuroToolResult` 真信封统一返回文本；`QuroRunCheckpoint` 每轮工具调用落盘。
- 上游拒答回执已归一化（不再把 `The request was rejected…` 原样糊给用户）。
- 详细：`docs/architecture/agent-loop/README.md`。

### 6.2 工具系统

- 235 工具注册 → 下发 → 执行 → 失败回喂，权威文档 `docs/architecture/tool-system/README.md`。
- 代表性工具：无障碍 `input_text`/`tap_screen`/`read_screen`（节点树非截图）、`launch_app`、`cms_*`、Agent 键盘 `ai_type_text`/`ai_press_enter`、`scheduler`、`memory_*`、`knowledge_*`（RAG）、`ui_widget`（60+ 可视化组件）、`visual_popup`/`visual_question`（模糊命令强制弹窗询问，禁猜测）、`run_code`（7 语言）、`apk_plugin`、`cluster_*`（9 个）。

### 6.3 特权层 L1–L5

`QuroPrivilegeManager` 统一审计：L1 无障碍（`service/QuroAccessibilityService`）→ L2 Shizuku（AIDL UserService 主路径）→ L3 DeviceAdmin → L4 ROOT（命令走 `sh -c`）→ L5 proot + Ubuntu 24.04 ARM64（`core/linux`、assets/linux_env）。未授权返回引导提示不静默越权。

### 6.4 终端子系统

`core/terminal/`：`QuroTerminalController` / `QuroShellSession`(PTY, terminal-core 的 libpty) / `QuroLinuxEnv`(proot)；前台服务 `QuroTerminalKeepAliveService`(specialUse) 息屏保活；ACI 跨进程 26 能力（单一入口 + action 分发）；4 种 IPC 接入（ContentProvider / Deep Link / Intent / BroadcastReceiver）；多会话。文档 `docs/features/terminal/`、`docs/TERMINAL_ARCHITECTURE.md`。

### 6.5 ACI（Agent Capability Interface）

同设备、无 Root、AIDL Binder 跨应用调用框架。受控端继承 `BaseACIService`，`Capability.create(id, description)` 的第 2 参是**给 LLM 的自然语言描述**（不是版本号，内部固定 version="1.0"）；受控端 Manifest 须写 `<queries>` 声明 ACTION_BIND/ACTION_WAKE 否则 Android 11+ 发现不到。手册：`docs/ACI_DEVELOPER_GUIDE.md`、`docs/ACI_TECHNICAL_ARCHITECTURE.md`；独立可构建源码在 **aci-core 分支**（AAR aci-core-release.aar v1.0.6+）。

### 6.6 插件框架（APK 级）

装一个 APK 给 AI 加能力，14 种扩展点（工具/ACI 能力/界面/指令…），AI 经唯一工具 `apk_plugin` 操控（install 带 `skip_signature_check` 仅本地调试）。插件经 DexClassLoader 跑在宿主进程。宿主侧引擎 `:plugin-engine`，契约 `:plugin-contract`（插件 compileOnly）。手册：`docs/PLUGIN_DEV_GUIDE.md`；分支 **apk-plugin-arch** 有重排版《APK 插件开发手册》。

### 6.7 Skills 与集群技能

- 内置技能：`assets/skills/zorv/`（67 个 md + manifest.json 含 SHA-256，首启播种；默认仅 design-studio 5 个启用）；`QuroSkill` 注册为 `skill__{name}` 工具。
- 集群技能 v2：`assets/cluster-skills/`（15 个 md + manifest v2 suite "cluster-v2"），独立 ClusterSkillEngine：依赖解析 + 工具需求校验 + RAG + 工具调用走 ZorvAI 主通道（#217/#218）。
- 文档：`docs/features/skills/`、`docs/features/cluster/`。

### 6.8 集群（多角色编排）

一个不可替换的「主持」驱动：定验收 → 拆解 → 点名 → 产出 → 裁决 → 收敛；9 个 `cluster_*` 工具；各角色绑不同厂商模型各走自己的 API 通道；角色发言实时投影进主对话框；配置入口 设置 → 多角色集群。验收连败到上限**降级放行并如实记账**（近期修复）；能力匹配跨中英。

### 6.9 引擎 / 运行时 / native

- **CMS 引擎**：共享运行时按需供给 NODE/PYTHON/SSH/JAVA/RUST/GO（`DepKind.ENV` + `CmsEnvProvisioner`），`cms_engine_status` 查就绪态/部署进度；CMS v2 模块（`core/cms`、`core/cms2`）。
- **Python**：端侧 CPython 3.14 原生引擎（PyEngine + libpython3.14.so）+ Scripting 沙箱（SandboxRuntime + HostApiDispatcher + GitHostApi + TsTranspiler）；另有 pybridge.c CPython 桥。
- **离线 LLM**：`QuroLocalEngineNative`（MNN/llama.cpp），流式 + `<think>` 思考段上屏 + 本地工具调用 + 会话常驻。
- **语音**：sherpa-ncnn 流式 STT（5 档模型 18–141MB）+ 多供应商 TTS（`QuroTtsHolder`，含小米 MiMo）。
- **app/src/main/jni 编 6 个 .so**：libquroplugin（QuickJS 插件引擎，含完整 quickjs 源码树）、libquropybridge、libtermux-terminal、libqurohost、libacihost、libfusiond。
- cmake/ 只有 `quro_git_source.cmake`（FetchContent 的 git 依赖 ref 解析辅助）。

### 6.10 UI 产出物六类渲染

对话内 AI 产物渲染管线（`docs/architecture/ui-rendering/`）：AIP 排版 / ui_widget 组件 / quro-ui DSL / GenUI / MiniApp / Mermaid。近期主线工作之一是**可视化组件（cards）**：正文围栏通道 + 结构化动作协议 + 名册驱动组件库（已到第三批，名册 92 组件）+ CardPatch（JSON Pointer 增量补丁，「外界→卡片」方向）+ 围栏属性 title=/theme=；「组件单一化根治」与「静默失效族五处缺陷」刚修完。

## 7. 开发操作指南（HOW-TO）

### 7.1 新增一个工具

1. 在 `core/tools/` 实现 `QuroTool` 接口（注意 `readOnly` 语义：默认 false = 有副作用 = 串行）。
2. 在 `QuroToolRegistry` 注册一行；若不进常驻 151，则挂到 `tool_router` 按需 `get_schema`。
3. 失败路径走 `QuroToolResult` 真信封回喂；补 i18n 字符串（11 语言，见 §7.4）。

### 7.2 新增/修改插件

1. 插件业务代码在对应 `plugin-*` 模块；契约只 compileOnly `:plugin-contract`（运行时宿主提供）。
2. `./gradlew :plugin-xxx:assembleRelease`；测试校验闸加 `-Punsigned`。
3. 签名必须与宿主一致（见 §2）；安装走 `apk_plugin` 工具或 `scripts/sign.sh` + `verify.sh`。
4. 扩展点共 14 种，详见 `docs/PLUGIN_DEV_GUIDE.md`。

### 7.3 新增 Gradle 模块（陷阱）

- 模块目录名与 Gradle 模块名**可能不同**：`:mnn`/`:llama` → `llm/`，`:codecanvas-*` 等 6 个 → `codecanvas/`，都靠 settings.gradle.kts 里 `project(...).projectDir = file(...)` 显式映射。**同步上游新增模块时必须同时改 include 列表和 projectDir 映射两处**。
- 仓库根名是 "Quro AI"；cluster 系列包名已去品牌化为 `com.ai.assistance.quro.cluster.*`。

### 7.4 i18n

11 语言；`scripts/` 下有翻译流水线（scan/translate/merge/audit）；AI 回复语言由统一注入器约束，覆盖主对话（云端+本地）、语音球、视频通话、GenUI Agent、IM 机器人、子智能体六条路径。文档 `docs/architecture/i18n/README.md`。

### 7.5 ACI 受控端接入（第三方 App）

5 步接入见 `docs/ACI_DEVELOPER_GUIDE.md`；最小示例见 `llms-full.txt` §4；受控端参考实现 `:aci-app`（演示）与 `:aidl-aci-browser`（生产级，仅放行主程序）。

## 9. 注意事项与陷阱

1. **git push 403 陷阱（本机已踩实）**：origin URL 不带用户名时命中 Windows 凭据管理器里 xiaoyuai1 条目 → `Permission to abidada/ZorvAI.git denied to xiaoyuai1`。修法（已应用）：`git remote set-url origin https://abidada@github.com/abidada/ZorvAI.git`。
2. **同步上游**：`git fetch upstream --prune` 后 main 用 `--ff-only` 快进；上游另有 aci-browser / aci-core / apk-plugin-arch 三个长存分支（均已建本地跟踪）。新增模块记得 settings.gradle.kts 双改（include + projectDir）。
3. **签名红线**（§2）：AI 可构建可跑 sign.sh，但绝不接触私钥内容；`.aiignore` 排除了 `local.properties`、所有密钥文件、`**/build/outputs/`；不弱化钩子、不 `--no-verify`。
4. **两把钥匙**：`app/zorvai-release-p12-v1cert.p12` 不是主签名密钥；宿主/插件必须同签名（DexClassLoader 同进程同权限，同签名是唯一信任源）。
5. **仅 arm64-v8a**；full/fdroid 双风味，fdroid 剔除一切预编译二进制——新增 native 依赖须考虑 fdroid 路径。
6. **Maven 必须走阿里云镜像**（本机直连不通），wrapper 也从阿里云拉。
7. **AGENTS.md 的 `scripts/setup-keystore.sh` 不存在**（文档与现实漂移）；llms.txt 的版本号（1.1.1）也落后于实际（1.1.5）——以 `app/build.gradle.kts` 和 git log 为准。
8. **GenUI 三代演进**：对话内 GenUI 画布 `genui_open` 已随 genui 模块删除（v1.0.96）；现存两套 = MiniApp（WebView）+ GenUI Agent（Compose，`genui_agent_open`）。别把旧文档里的第三套当现状。
9. **闸门/策划不可关**：交付闸门与任务策划是 Agent 固有环节（v1.1.x 已定），不存在「关掉闸门」的开关。
10. **历史遗留**：根目录散落多份专题报告 md（CMS引擎依赖修复报告 / OVERVIEW_* / overview-*-fix.md）；`scripts/_fix*.py` 是一次性修补脚本；`docs/` 顶层混有 BUG 总结、营销文（csdn-article）、ROADMAP——找文档优先走 §10 索引。
